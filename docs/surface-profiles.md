# Surface profiles

Shared foundations create recognition; surface profiles protect usability.

## Website

The marketing site may use larger type, broader spacing, editorial composition,
and selective brand primitives. Its job is to explain value and establish
trust without oversimplifying technical ownership.

Every surface obeys the same limit on identity density: **at most one signature
device per viewport.** The mark, a manifest plate, and the signature diagram
must not share a screen. Over-application is this system's most likely failure.

## Documentation

Documentation prioritizes search, hierarchy, reading measure, stable anchors,
code legibility, and dense navigation. Decorative treatment must not compete
with technical content.

Two devices are expected here:

- **A front-matter block** on every page — status, applies-to version,
  platforms, prerequisites, and reading time, set as a ruled monospace block.
- **`Failure mode` and `Not covered` callouts**, which give the voice's candour
  a permanent place in the layout rather than leaving it to each author.

Typography splits by page kind: reference and task pages stay in Public Sans,
conceptual and Learn pages switch to Newsreader. The family tells the reader
which kind of page they are on before they read a word.

## Console

The console prioritizes account state, licensing decisions, billing actions,
confirmation, and recovery. Actions and status use explicit language and
predictable placement.

License state renders as a **forward-only lifecycle stepper** — evaluating,
licensed, active, renewal due — drawn as a linear stepper that never moves
backward.

## Build and integration pages

Any page that tells a developer to send data carries the **Opacity Ledger**: a
four-column table of what stays local, what crosses the wire, what the relay
stores, and what is visible to the relay. It is the honesty line in tabular
form, and it appears on every Build page rather than on a single dedicated one.

## SDK repositories

SDK READMEs and generated API references use the organization mark, typography
guidance, code colors, and approved social assets. They do not take a runtime
dependency on UI components.
